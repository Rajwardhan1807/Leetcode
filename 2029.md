# LeetCode 2029 - Stone Game IX

## Problem Statement

Alice and Bob play a game with a row of stones. Each stone has an associated value.

On each turn, a player removes one stone. The player who removes a stone when the **sum of all removed stones becomes divisible by 3** loses.

Alice plays first.

If there are no remaining stones, Bob wins automatically, even if it is Alice's turn.

Return `true` if Alice wins when both players play optimally. Otherwise, return `false`.

---

## Examples

### Example 1

```text
Input:
stones = [2,1]

Output:
true
```

Alice can remove `1`, making the sum `1`.

Bob must remove `2`, making the sum `3`, so Bob loses.

---

### Example 2

```text
Input:
stones = [2]

Output:
false
```

Alice has to remove the only stone.

The sum becomes `2`, which is not divisible by `3`.

There are no stones left, so Bob wins automatically.

---

## Approach

The actual values of the stones are not important.

Only their **remainder when divided by 3** matters.

Every stone belongs to one of three groups:

```text
x % 3 = 0
x % 3 = 1
x % 3 = 2
```

We count how many stones belong to each group.

```cpp
cnt[0] → Number of stones with remainder 0
cnt[1] → Number of stones with remainder 1
cnt[2] → Number of stones with remainder 2
```

### Why do remainders matter?

The running sum can only have three possible remainders:

```text
0, 1, 2
```

A stone with remainder `0` does not change the remainder of the sum.

A stone with remainder `1` changes it by `+1`.

A stone with remainder `2` changes it by `+2` (equivalent to `-1` modulo 3).

The game therefore depends only on the counts of these three types.

---

## Key Observation

### Case 1: Number of remainder-0 stones is even

If:

```text
cnt[0] % 2 == 0
```

then Alice can win only if both remainder-1 and remainder-2 stones exist.

```text
cnt[1] > 0 && cnt[2] > 0
```

---

### Case 2: Number of remainder-0 stones is odd

If:

```text
cnt[0] % 2 == 1
```

then Alice wins when the difference between the number of remainder-1 and remainder-2 stones is greater than `2`.

```text
abs(cnt[1] - cnt[2]) > 2
```

These conditions capture the optimal-play strategy without simulating every possible move.

---

## Algorithm

1. Create an array `cnt[3]` initialized to zero.
2. For every stone:

   * Calculate `stone % 3`.
   * Increment the corresponding counter.
3. If `cnt[0]` is even:

   * Return whether both `cnt[1]` and `cnt[2]` are greater than zero.
4. Otherwise:

   * Return whether `abs(cnt[1] - cnt[2]) > 2`.

---

## Dry Run

### Input

```text
stones = [2,1]
```

Calculate remainders:

```text
2 % 3 = 2
1 % 3 = 1
```

Therefore:

```text
cnt[0] = 0
cnt[1] = 1
cnt[2] = 1
```

Since:

```text
cnt[0] % 2 == 0
```

we check:

```text
cnt[1] > 0 && cnt[2] > 0
```

Both are true.

Therefore:

```text
Output = true
```

---

## C++ Solution

```cpp
class Solution {
public:
    bool stoneGameIX(vector<int>& stones) {
        int cnt[3] = {0};

        for(int x : stones)
            cnt[x % 3]++;

        if(cnt[0] % 2 == 0)
            return cnt[1] > 0 && cnt[2] > 0;

        return abs(cnt[1] - cnt[2]) > 2;
    }
};
```

## Complexity Analysis

### Time Complexity

```text
O(n)
```

Each stone is processed exactly once.

### Space Complexity

```text
O(1)
```

Only three counters are used regardless of the size of the input.

## Key Takeaway

The main trick is to ignore the actual stone values and consider only their remainders when divided by `3`.

Once the stones are grouped into remainder `0`, `1`, and `2`, the game can be solved using a few simple conditions instead of simulating every possible game state.
